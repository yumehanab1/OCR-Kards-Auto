# M3:出牌逻辑,悬停识别方案

这是当时定下来的设计。核心想法是:鼠标悬停到手牌上,游戏会把那张牌放大显示在
屏幕中间,放大卡上费用和类型图标都看得清清楚楚,读那张放大卡比直接读手牌靠谱得多。

## 识别链路

整个流程是全离线的,不联网。

我方回合开始,从左到右扫描手牌热区,每张牌大概占 50 到 100 像素宽。把鼠标移到
第 N 张牌上,悬停位置大约是 y=700。截一张图,然后识别放大卡上的两个东西。

一是费用徽章,在放大卡左上角,白字数字配金色的 K,深色底,用模板匹配读。
二是类型图标,在卡名正上方居中的深色小方块里,也用模板匹配。

图标一共六种:小人是步兵,坦克是坦克,飞机是战斗机,小炸弹是轰炸机,
感叹号是指令卡,问号是反制卡。

读完就做决策,然后移到下一张。

## 放大卡长什么样

从上到下大概是这个顺序:左上角是费用徽章,然后往下是类型图标,图标下面是卡名文字,
再下面是效果描述。

位置会随着你悬停的是哪张牌而变,整个面板是跟着卡走的。所以类型图标和费用徽章都
用整屏模板匹配来找,不能裁一块固定区域。

## 六种图标对应什么

步兵、坦克、战斗机、轰炸机这四种是单位,能主动部署到战场上。战斗机和轰炸机占空军位。

感叹号是指令卡,多数需要选目标,第一版不打。

问号是反制卡,盖放逻辑比较复杂,也不打。

## 决策规则

第一版写得很保守,就一条规则:

对第 N 张手牌,读出费用 C 和类型 T。如果 T 是四种单位之一,而且 C 不超过当前费用,
就尝试拖出去部署。拖了 1.5 秒还没成功,就放弃这张牌,并且在备忘录里标记本回合不再
碰它。其他情况一律不打,直接看下一张。

所有牌都处理完,结束回合。

## 还没做的

要用 template_capture.py 采集费用数字徽章(0 到 9 加 K 那个图标)和六种类型图标。

要写悬停扫描器,按热区模型自动从左到右悬停每一张牌。

决策循环要接进 main_loop 的 in_game 状态。

最后要实机验证一整轮出牌。

## 已知的限制

两张一样的牌(比如两张轻步兵)热区挨在一起,悬停没法区分是哪一张。不过不影响决策,
因为同费同效果,打哪张都一样。

手牌张数一变,热区位置就跟着变,所以要么做张数检测,要么动态扫描。这个坑不小。

第一版不打指令和反制,会错过一些机会。但换个角度说,它绝不会犯错。安全优先。
