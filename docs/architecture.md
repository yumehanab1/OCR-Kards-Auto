# 当前架构

这份文档描述当前代码的真实运行链路。早期 M0–M3 文档记录设计过程，遇到冲突时以代码和本文件为准。

## 运行链路

```text
KARDS AUTO.exe
    └─ src/gui.py                 面板、参数收集、日志展示
         └─ src/main_loop.py      单实例保护、截图、状态机、结算流程
              ├─ src/ui_state.py  主菜单/选牌/排队/换牌/对局/结算识别
              └─ src/turn_engine.py
                   ├─ hand_scanner_v2.py  手牌识别
                   ├─ hand_cost_filter.py 橙色费用候选、旋转字形及费用组合
                   ├─ card_match.py       卡名、费用、类型
                   ├─ board.py             战场和总部
                   ├─ deploy.py            部署拖拽
                   ├─ order_choice.py      两牌/三牌选牌阶段与连续选牌
                   └─ attack.py            上前线和攻击
```

面板 exe 只负责界面。发布包里的 `python\python.exe` 会重新读取发布包中的 `src\`、`config\`、`ui_templates\` 和 `card_db\`，所以修改引擎代码后不需要把代码编进 exe；修改 `src/gui.py` 后必须重打 exe。

## 运行时输入

PC 默认惰性路径先由 `hand_cost_filter` 在收起扇形的一帧中筛橙色费用数字，仅对候选
悬停确认身份和费用。合法候选按预算、支援线空位和指令目标计算最大总费用组合；
同费用优先多出牌，每次出牌后重新定位并对账。身份缓存只在主牌视觉一致时使用，
不把部分橙色候选写入按全手牌次序索引的 HandMemory。缺样/歧义退回原扫描，回退
候选在抓点复核身份。当前模板校准 1/2/3/4/5/6/7，0/8/9、两位费用及改费效果仍需
补样。`KARDS_ORANGE_SCAN=0` 可恢复原扫描和提前收手规则。

| 目录/文件 | 作用 | 维护规则 |
|---|---|---|
| `src/` | 引擎和面板源码 | 运行时模块放根目录；废弃实验放 `src/archive/` |
| `config/templates.json` | 模板路径与 ROI | 加模板时同时提交 PNG 和区域 |
| `ui_templates/` | 按钮、图标模板 | 只放运行时需要的模板 |
| `config/kredits_digits/` | 费用数字模板 | 不要移到 `shots/`，发布脚本会检查它 |
| `config/order_plays.json` | 指令卡规则表 | 由 `dev/order_plan.py` 生成，避免手改 |
| `config/update_manifest.json` | 发布包内的文件 SHA-256 清单 | 由 `make_release.py` 生成；用于核对与用户触发的增量更新 |
| `card_db/kards_data.json` | 卡名、费用、类型 | 运行时必需，不是测试夹具 |
| `logs/` | 本机运行日志 | 不提交、不打包 |
| `shots/` | 本机截图和取证材料 | 不提交、不打包 |

## 状态机边界

面板更新检测由 `update_check.py` 查询 Release，`update_install.py` 严格核对配套 PC 清单。
“应用更新”由用户点击；自动对局运行时不能应用，准备及安装阶段持有引擎互斥锁。
清单相同文件不写入；本机设置、学习哈希、日志、截图、手机版和交接资料受保护。
下载通过 HTTPS Range 读取 ZIP 目录与所需成员，服务器不支持分段时一次完整下载；每个成员
须符合清单大小与 SHA-256。所有下载在 logs/updates/<任务>/new 内完成后才允许安装。
清单build记录内容标识、构建时间及源码提交；同版本仅在已有本地清单且远端构建较新、内容不同的情况下允许应用。
独立助手等待面板进程退出，再逐文件原子替换；先备份，版本及本地清单最后写入。
检测后本地有新修改会取消替换。失败按事务记录恢复；崩溃保留安装意图和备份，下次面板提供恢复按钮。
若更新涉及 python/，助手使用暂存的独立 Python 副本，避免替换自身加载的 DLL。
不删除清单未列出的本地额外文件。旧面板需一次手动换新；后续无需重新解压整目录。

同名天气指令由 `weather_cards.py` 根据手牌悬停描述匹配 `config/weather_variants.json`
中的 27 个版本，再以独立规则键进入 `orders`。纯卡名/卡图指纹不放行未分版本的天气牌，
天气不复用橙色身份缓存，拖出前重新核对版本。选项菜单的布局识别和随机选择不读取标题。
原始图 500px 与 240px 缩图 OCR 回放通过，尚需手牌实机缩放/动画回归。

描述提取在卡名下方按行距截取连续段落，遇到空白断层停止，不把下方手牌标题拼入。
短描述仍要求完整匹配，长描述保留原分数与唯一性条件。费用组合至多含一张天气；
回合引擎在确认天气扣费成功后标记本回合已用，后续候选跳过天气，下回合清除标记。
守护来源只采用完整盾牌；敌方支援线直接邻接总部的守护可补证总部保护，不跨过中间卡，
也不把前线守护套到后排总部。轰炸机随机选择前线目标同样过滤被保护目标。

零预算仍核查橙色候选并允许已确认 0 费牌；无可靠候选时不触发全手牌或盲扫。
旧扫描共享 12 秒协作式预算，嵌套回退不能重置时限；当前 OCR 结束后才可中断。
未扣费的拒绝归还预扣费用，结果未知则重读费用，读不出不擅自退款；通用失败不生成
`learned cap`，连续两张未确认打出结束当前出牌阶段。指令不按空槽冲突再次拖拽。
攻击/移动后刷新当前战场；可信当前单位数优先于累计部署数。单位攻击后验未知停止本段攻击。
`find_enemy_hq` 只在实际敌方支援区查找，不能拿第一个剩余行（可能是我方）代替敌方。

`main_loop.py` 只负责跨页面推进：

1. `main_menu`：点击主页面左上进入卡组选择；
2. `deck_select`：按普通/训练/排位模板选择模式，再点击开始；
3. `queueing`：等待匹配，超时取消并重来；
4. `mulligan`：确认换牌；
5. `in_game`：交给 `TurnEngine`；
6. `victory` / `defeat`：完成结算补点，回到主菜单。

回合引擎成功点击结束回合后把光标停到右侧空白处，避免下一回合按钮的橙色悬停
样式干扰白色模板识别。输入失败保留 end_turn 阶段和原账本，不执行光标停放。

空白画面判据先于页面动作。暗色领取奖励页可能平均亮度低于 10，因此仅在
`dismiss` 已开启时，按客户区比例检查中央奖励图案和底部领取字区的亮像素；
两处均满足条件才允许继续原有结算补点。窗口可见性检查仍须通过，未知画面本身
不会开启补点。`main_loop.POST_MATCH_DARK_REWARD` 可关闭该识别例外。

选牌画面优先于普通对局处理：每个可操作画面检查三牌布局，识别到后进入 `selection_pending`，不要求知道上一张打出的牌。两牌抉择按 `orders.py` 中已标左/右的规则选择；三牌按等概率随机选择。单位部署、攻击或移动触发的三牌同样交给这个阶段；攻击和移动发现弹窗后暂停原有战场判定。一次点击后继续观察下一组选牌，稳定回到正常对局后才恢复之前阶段；无法确定规则或结果时进入 `selection_blocked` 并留帧。独立总开关为 `order_choice.ENABLE_SELECTION_STAGE`。

当前坐标及布局只校准了 1280×720 客户区。`dev/choice_test.py` 使用本机截图验证；离线通过不代表游戏内通过。

战场总部定位除原亮面掩码外，还可按四边连续证据、下部居中血量盾牌与无单位费用徽章
补检。盾牌提供候选位置时，仍须确认整张卡的四边和正常完整卡尺寸，不凭数字单独造总部。
规则对敌我双方相同；完整且可读的旧 HQ 框优先保留，避免发光边缘抬高行带。
`board.EDGE_HQ_RECOVERY=False` 关闭补检；`TABLE_OUTLINE_GUARD=False` 关闭桌面纹理过滤。
桌面过滤保留孤立费用徽章和清晰已判色的数字；弱行带猜测需要卡框或攻/类/防三个牌子支持。
已确认 HQ 范围内的标题、国家图案不再充当单位徽章。血量宽字形仅在内部有明显细颈时拆分，
`hq_hp.SPLIT_JOINED_DIGITS=False` 可关闭；不因总部皮肤名指定血量或攻击位置。

特殊总部素材的离线测试保持源截图宽高比，仅等比例缩放与补边；素材合成只验证颜色/纹理
和两侧布局，不替代游戏内真实渲染。运行引擎的客户区要求仍为 1280×720。
双牌抉择使用出牌前已记录的白名单选边规则，不读取弹出选项的卡名。两张牌的亮面、
底边和连续边框须完整出现；连续至少两帧、相对稳定期起始画面变化很小且持续
0.5 秒后，直接点击已标注坐标。双牌边框兼容真实截图中悬停放大造成的左移 5 像素，
面板、底边和边界对比仍须满足原判据。从拖牌前创建选牌流程起，六秒仍未稳定则停手留帧。
未标左右、缺少原出牌上下文和后续未知双牌菜单均不选；同一画面不重复点击。
`titles_match()` 只供离线 OCR 排障探针使用，不参与双牌运行判断。
双牌后方亮色战场卡遮住左侧外缘对比时，只有两张固定费用底板均成立、左框仍连续，
且右侧外框连续并与外侧有足够对比，才允许补证；整体亮面、底边和稳定期仍须满足。
三牌选边默认等待完整布局连续两帧稳定后等概率随机选择，不读取选项标题；
亮面、连续边框、底边和天气光照下的费用暗底仍参与布局检查。开发、预报和单位触发
共用此流程。`VERIFY_THREE_TITLES=True` 可启用旧标题核对供诊断：三个已知标题连续
两次一致，总时限六秒，超时停手。下一组选项仍留在
同一选牌阶段，不会因第一次点击而恢复普通对局。

识别不到状态时必须保持 `fail-closed`：记录 `state -> None` 并等待，不凭猜测点击。

## 新文件放哪里

- 新的运行时模块：`src/` 根目录，并在本文的运行链路中登记。
- 新的离线回归：暂放 `dev/`，文件名以 `_test.py` 结尾，并在 `dev/README.md` 登记。
- 新的探针/A-B 工具：暂放 `dev/`，用 `_probe.py`、`_ab.py`、`_diag.py` 或 `_timing.py` 区分用途。
- 新的设计、排障和实机报告：`docs/`，按 `design/`、`generated/`、`reports/`、`archive/` 的语义归类。
- 临时截图、日志、拼图：`shots/` 或 `logs/`，不要放根目录。
- 根目录只保留用户入口、安装/构建脚本、许可证和顶层说明。
