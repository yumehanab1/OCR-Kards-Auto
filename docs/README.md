# 设计文档

这里的几份是项目**开工时和早期**的设计记录，按里程碑排列。技术选型后来有变动
（例如费用数字最后走的是模板匹配而不是 OCR、手牌识别从全量扫描改成惰性扫描），
所以看的时候以代码为准；它们主要用来回答「当初为什么这么选」。

| 文件 | 内容 |
|---|---|
| [KARDS图像识别刷级方案.md](KARDS图像识别刷级方案.md) | 开工前的完整工程方案：目标、约束、里程碑划分、技术选型 |
| [M0_README.md](M0_README.md) | M0：环境、窗口控制、DPI、双通道截图与标定工具 |
| [M1_README.md](M1_README.md) | M1：界面状态分类（UI 模板匹配，8 个模板） |
| [M2_README.md](M2_README.md) | M2：主循环调度器（主菜单 → 对局 → 结算 → 下一局） |
| [M3_设计定稿.md](M3_设计定稿.md) | M3：出牌逻辑与悬停识别方案 |

跑游戏**不需要**这个目录。想改识别逻辑的话值得先翻一遍：里面记着不少
「为什么不用另一种做法」的结论。当前的实现细节、判据和踩坑记录在
[CONTRIBUTING.md](../CONTRIBUTING.md) 和代码注释里。

## 文档边界

`docs\` 里的文件分成三类，阅读时按下面的边界判断来源：

| 类别 | 文件 | 说明 |
|---|---|---|
| 早期设计档案 | `KARDS图像识别刷级方案.md`、`M0_README.md` ~ `M3_设计定稿.md` | 已纳入仓库，记录当时的方案和取舍；实现细节以当前代码为准 |
| 当前生成文档 | `指令卡清单.md`、`打不出去的指令卡.md`、`order_cards_*.md` | 由 `dev\` 下的生成器或核对脚本产出，修改判据后应重新生成或核对 |
| 实机/会话档案 | `PC_STATE.md`、`MOBILE_STATE.md`、`ORDER_CARDS_REAL_TEST.md`、各轮实机报告 | 不随 Git 仓库提供，可能只存在于开发树或组装副本；代码中的编号引用指向这些外部档案 |

最后一类不应为了补链接而复制进仓库：它们会随每轮实机记录持续增长，且不是运行时输入。需要补充项目记忆时，请在当前文档或 `CHANGELOG.md` 留下可复现的结论，而不是把整份本机状态档案提交进来。
