# M2:主循环调度器

M1 解决了"知道自己在哪",M2 把这件事变成一个能自己点按钮走下去的循环。

## 它走的流程

    主菜单       点 play_btn
    选牌组       先点 casual_mode_btn,再点 deck_ok_btn
    排队中       等着,超过 12 分钟就点取消重来
    换牌         点 mulligan_ok_btn
    对局中       M2 里只有可选的自动结束回合,M3 才加出牌
    胜负结算     点结算按钮
    回主菜单     自动开下一局

## 怎么跑

干跑,只打印决策绝不点鼠标,拿来测试最合适:

    .venv\Scripts\python.exe src\main_loop.py --dry-run --max-ticks 10

真跑,会真的动鼠标,记得让 KARDS 窗口保持前台可见:

    .venv\Scripts\python.exe src\main_loop.py

真跑并且在对局里自动点结束回合:

    .venv\Scripts\python.exe src\main_loop.py --end-turn

参数一共这几个。--dry-run 只记录将要点击什么,不动鼠标。--max-ticks N 跑 N 轮循环
就退出,测试用。--max-rounds N 打完 N 局退出。--end-turn 让对局里每隔随机 20 到 45 秒
点一次结束回合,这是 M2 的占位行为,目的是让对局能自然结束,真正的出牌留到 M3。

想停随时 Ctrl+C。

## 内置的几条安全机制

同一按钮不会狂点。每次点击后有 2.5 秒冷却。

画面全黑或全白连续 6 帧就暂停动作,等你把窗口放回前台。

模板匹配分数低于 0.6 就不点,避免误点。

模板里的坐标是客户区坐标,点击前会转成屏幕坐标,所以窗口摆在屏幕哪个位置都能点对。

日志写在 logs\main_loop.log,每一轮认出什么状态、做了什么动作都有记录。

## 跑之前的三个前提

KARDS 窗口要保持前台可见,不能被完全遮挡,截图通道需要这个。

保持 1280x720。启动时会沿用你上次的尺寸,如果尺寸变了先跑一次 snap 修回来。

卡组要放在第一位。因为选牌组那一步是固定点第一个卡组,所以把要挂机的卡组放第一。

## 实测时该看什么

停在主菜单,然后实跑,看它是不是自动完成了这几步:点对战、选休闲、确定卡组、开始排队。

排进对局之后,换牌页有没有点确定,有没有正常进入对局。

打完一局之后,结算按钮有没有点掉,有没有回到主菜单并且自动开下一局。

哪一步不对就把 logs\main_loop.log 发出来,照着实际行为修状态机。
