KARDS AUTO v0.1.6

这是电脑版,Windows 64 位用的。手机版不在这个包里。

先说它是干嘛的:你自己把 KARDS 打开,它替你打下去。它不读游戏内存,也不碰游戏文件,
全靠看屏幕 —— 认出现在是哪个界面、场上有什么牌,然后动鼠标出牌、上前线、攻击、结束回合。
说白了就是"看屏幕 + 动鼠标",跟你自己坐在这儿点是同一回事。

好处是它每一步都写进日志里,你随时能看见它在想什么。坏处也在日志里,后面会说。


一、开跑之前

  - Windows 10 / 11,64 位。就是在这个系统上做的,别的没测过。
  - KARDS 电脑版得先开着,而且要停在能进对局的界面。停在主界面就行,
    选牌组、排队、换牌这些它自己会做,你不用管。
  - 游戏窗口别最小化 —— 最小化就抓不到画面了,日志里会写 blank frame。
  - 窗口化、无边框、全屏都行。它会自己把游戏客户区拉成 1280x720,
    拉不动或者拉完尺寸不对,它会打一行日志提醒你。

不用装 Python,不用管理员权限。要用到的东西都打包在 python 文件夹里了 ——
那是一份便携 Python,连同所有依赖一起带着走,解压到哪个目录都能跑
(路径里有中文、有空格都不影响)。


二、三步开始

  1. 开 KARDS,进到主界面，开设置，分辨率调成1280x720，显示模式选窗口。
  2. 双击 KARDS AUTO.exe,弹出一个面板窗口。
  3. 在面板上把"跑几局"填好,点"开始"。然后就可以不管它了。想停随时点"停止"。

日志会实时显示在面板右边,同时一行行写进 logs\main_loop.log。


三、面板上都是什么

右上角三个按钮:

  检测更新   查新版本。会去 GitHub 上读这个项目的发布页,和你本地的版本号比:
             有新版本就告诉你版本号和包多大,再把按钮变成「打开发布页」,点一下就
             用浏览器开下载页。**它不会自己下载、更不会自己替换** —— 这个包是
             130 MB 的便携目录,替换正在运行中的自己很容易换个坏包出来。
             查不到(没网、被限流、公司代理挡住)时会如实说查不到,**不会**
             假装"已是最新"。
  开始       启动引擎。它会自己走完整条流程:主界面 → 选牌组 → 排队 → 换牌 →
             打整局 → 结算 → 再来一局。
  停止       把引擎进程结束掉。当前那一下鼠标动作可能停在半路(比如牌拖到一半),
             重开一局就行。

左栏"功能选择"这些开关,其实都是给引擎的命令行参数,面板只是帮你勾。想省事就全用默认:

  自动打完一局 (--play)     默认开。部署 + 出牌 + 结束回合。不勾它就只看不动。
  攻击 (--attack)           默认开。按规则表挑攻击者和目标,带守护/拦截的判据。
  惰性扫描 (--fast-scan)    默认开。找到第一张出得起的牌就停手,省时间。
                            关掉就是每回合把整手牌读一遍 —— 慢,但信息全,排查的时候有用。
  结束回合 (--end-turn)     默认关。出完牌主动点"结束回合";不点就等游戏自己的回合计时。
  只看不动 (--dry-run)      默认关。只记决策、绝不动鼠标。第一次用建议先把它勾上,
                            盯着日志看它认屏认不认得对。
  跑几局                    默认 3。填 0 就是一直跑下去。

一个开关都不勾,点开始会被拒绝,它会说"至少勾一个再开始"。

中间"实时状态"那块显示:现在认出的是哪个界面、费用读数、我方支援几张、
最近一个动作、这一段跑了几局、这次启动带了哪串参数。底下还会挂个标签,
"本段干净"就是没异常,如果是"值得看一眼 N",说明日志里出现了异常行,
建议你自己翻一眼。

右边"日志"就是 logs\main_loop.log 的实时尾巴。上面两个小按钮,
一个"只看关键行"帮你过滤噪音,一个"到底部"让它跟着滚。


四、跑的时候别用面板把 KARDS 盖住

这条最容易踩。它抓屏是直接抓屏幕的,窗口被完全挡住的时候,抓到的就是别人的画面,
于是引擎内置了一条规矩:看不清就什么都不做,免得照着假画面瞎点。挡住的时候日志会写:

  ⚠️ KARDS 窗口不可见/被遮挡 -> 本 tick 不动作。…… 请把 KARDS 置于最前,别让别的窗口盖住它。

要么把面板拖到旁边,要么点完"开始"就把游戏切到前台。等它重新看清了,
会自己接着跑,并写一行"✅ KARDS 窗口恢复可见"。

另外,同一个游戏只能跑一个它。重复双击 exe 开两个面板、或者自己又手动起一个引擎,
两个会抢同一个鼠标,扫描会被自己人打断(引擎启动时有单实例锁挡着)。


五、它会做什么,不会做什么

会:

  - 认出主界面、选牌组、排队、换牌、对局中、结算(胜/负)这几种画面,自己一路点进去;
  - 排队超过 12 分钟会自己点取消,重新走一遍流程;
  - 对局里读费用、扫手牌,把出得起的单位拖到场上;
  - 让场上的单位上前线、攻击敌方单位和总部;
  - 打不动了就结束回合,一局完了自己开下一局;
  - 顺手把升级、任务完成那类弹出来的尾巴页点掉。

不会(先说清楚,免得你等它):

  - 不会读对手的牌,也不会做什么战术推演。它的策略很朴素:"能出的出、能打的打、打不动就过";
  - 不会用那些需要手动选目标的指令卡;
  - 不会自动登录、不会自动更新、不改你的游戏设置;
  - 不认识中文以外的游戏语言,也不认识改过 UI 缩放比例的界面 —— 游戏的 UI 缩放请保持默认。


六、出问题了怎么办

面板右边就是日志。想看全文就打开 logs\main_loop.log(引擎写的),
logs\gui_run.log 是面板把引擎输出原样抄的一份,两个都能看。

对得上号的几种情况:

  state -> None 一直重复
      认不出当前画面。多半是游戏弹了公告、活动、升级之类的窗口挡在前面,关掉它。

  blank frame - window minimized/occluded?
      抓到的画面是空的。游戏窗口被最小化,或者被别的窗口完全挡住了。

  ⚠️ 没找到 kards 窗口(后面每次 tick 都会重新找)
      游戏没开。它认窗口是认进程名里带 kards、窗口类是 UnrealWindow 的那个,
      所以游戏没开的时候它宁可空等,也不会抓错窗口。

  ⚠️ KARDS 窗口不可见/被遮挡 -> 本 tick 不动作
      就是上面第四节那条。把游戏拉到最前就行。

  [attack] 没找到橙色费用徽章 -> 不攻击
      认不出费用徽章(不是你的回合,或者画面还卡在动画上),这一下它就不出手,
      等一会儿自己会重试。

  鼠标在动,游戏却没反应
      游戏不在前台,点下去落到别的窗口上了。点一下游戏窗口,回面板点"停止",再点"开始"。

还有一招:把 logs\ 里最新的日志整份发给作者,基本上一眼就能看出卡在哪。


七、文件夹里都是什么

  KARDS AUTO.exe     双击这个
  README.md          你正在看的这份

  src\               引擎的代码。运行时真的会去读它,别删
  config\            界面模板、识别参数、版本号。别删,删了要重新录
  ui_templates\      按钮和图标的小图。别删
  assets\            图标
  python\            便携 Python + 全部依赖,300MB 就在这儿。别删
  logs\              运行日志,出问题看这里
  cards\ database\   数据目录,现在是空的,程序会往里写

  dev\               开发和调试用的小脚本,跑游戏用不到,可以整个删掉
  docs\              设计文档和历史记录,跑游戏用不到,可以整个删掉
  install.cmd        一键装依赖。从源码跑的话先双击这个
  build_gui.bat      重新打包 exe 用的,只有改界面才需要
  calibrate.cmd / snap-kards.cmd   重新标定识别区域用的,平时用不到
  requirements.txt   依赖清单。装依赖交给 install.cmd,不用手敲

要紧的一句:exe 只是个"面板",真正干活的是它去调 python\ 里的 Python 跑 src\main_loop.py。
所以 python\、src\、config\、ui_templates\ 一个都不能少。整个文件夹一起挪、一起拷
都没问题(便携 Python 的路径全跟着自己的位置走,不认死路),但别只把 exe 单独拎出去。

★ 这里踩过一次坑,值得说一句:上一版发出去的是 .venv,而 venv 这种东西**换台机器
  就不能用** —— 它记着建它那台电脑的 Python 装在哪,别人机器上没那个目录,一点开始
  就报"退出码 103",而且日志里一个字都没有。现在换成了便携 Python,面板在启动引擎
  之前还会真的试跑一下解释器,不对就直接告诉你哪不对、该怎么办,而不是甩一个数字。


七点五、从源码跑的话

如果你没拿 Releases 的压缩包,而是自己 clone 下来跑的,那 python\ 是没有的
(git 里不放几百 MB 的二进制),得先装依赖。
双击 install.cmd 就行,它会自己找 Python、建一个 .venv、装包,最后 import 一遍确认没坏。

装完之后面板会自动用这个 .venv。它找解释器的顺序是:便携 Python → .venv → PATH 里的
Python,而且**每一档都真的跑一次确认能用**,坏的会跳过 —— 所以"某个环境是坏的"不会
让整个面板用不了,它会挨个试完再告诉你哪个不行、为什么不行。

它认三个参数:install.cmd minimal 只装跑引擎必需的那四个,最快;install.cmd mirror
走清华镜像,国内网络快很多;两个可以一起用。

要求 Python 3.10 以上。没装的话脚本会告诉你去哪下,装的时候记得勾上
"Add python.exe to PATH"。

关于那个读卡牌描述的 OCR:它在 PyPI 上声明的 Python 支持上限是 3.12,pip 在更新的
版本上有时会直接说"找不到可用版本"。但这不绝对 —— 发布包自带的 Python 3.14 上就
装上了,实测能认出模板图上的字。真装不上也不影响跑,只是少个读卡牌文字的功能,
install.cmd 会跳过它继续往下走。


八、几句实话

  - 这是自动化操作。虽然只是模拟鼠标键盘,但理论上仍然有被官方判定为第三方工具的风险。
    用不用、用在哪个账号上,你自己判断。
  - 它的水平大概是"一个不太动脑子但手很快的玩家":会出牌、会攻击,但打不过会玩的真人,
    局面一复杂就容易输。
  - 输赢本来也不是重点,这工具一开始就是拿来刷等级、刷任务的。


九、版本和许可

现在是 v0.1.6,版本号写在 config\app_version.json 里。
"检测更新"会去 GitHub 读本项目的发布页,和这个号比 —— 想让别的地方也能查,
把 `app_version.json` 里的 `update_url` 填成你的地址就行(留空 = 用 GitHub)。

v0.1.6 修的是"**卡在某个界面不动了 / 点了没反应**"这一类里最坑的一种:

  - 有用户报"运行到卡组页面不会点确定"。拿到日志一看,**不是不会点,是点下去程序就退出**:
    系统的 `SetCursorPos`(移动鼠标)抛了异常,而当时没人接,异常一路冒到顶层 ->
    程序记下错误就结束了。界面上看起来就是"停在那儿不动"。
  - 现在**鼠标动作全部软着陆**:动不了就如实说"这一下没点成"并继续跑,不再整轮退出;
  - ★ 而且**挪不过去就绝不按下去** —— 光标没到位时按下/松开,点的是光标当时所在的地方,
    可能正好是别的窗口的按钮,比"这一下不点"危险得多;
  - 拖拽半路动不了会**松手**再报失败,不会让鼠标一直按着;
  - 连着失败几次会提示原因:**游戏/Steam 用管理员身份运行时,本程序也必须用管理员身份**,
    否则 Windows 会挡住我们对游戏的点击(同一次运行里往往还会看到
    "设置窗口尺寸失败 … 拒绝访问",那是同一个病)。
  - 另外:引擎里"回合引擎出错"那一行以前只报一句异常消息,**现在第一次带完整堆栈** ——
    没有它,报告里的错误只能靠猜(这份日志里就有一个 `IndexError` 因此查不出在哪一行)。
  - ★ 另一位用户报"鼠标一直不动",还提了一条很实在的:**"异常退出后要去任务管理器
    把 Python 进程关掉,不然会说有两个实例"**。查下来是我们自己的问题:
    **关掉面板不会带走引擎那个子进程** —— 它继续活着、占着"只许一个实例"的锁,
    于是下次点开始直接被拒(那份日志里"拒绝启动第二个实例"出现了 **48 次**)。
    现在:**关面板会把引擎一起停掉**;万一还是被拒,日志会直接写出
    **占用者 PID** 和一条能照抄的命令(`taskkill /PID 1234 /F`)。
    ⇒ 以后**不需要再去任务管理器翻进程**了。
  - ★ 结算页(打完一局之后那些"点一下跳过"的界面)的点击位置改了:
    以前是在**屏幕正中附近**轮换着点,而用户两次实测都说**点中心不生效**。
    现在首选 **左起 3/4、竖直居中**那一点(1280x720 下就是 `(960,360)`),
    并且**不再点屏幕正中**;旁边留了几个同样不居中的备选点轮换(某个位置在
    某些界面上会失效,只点一个点会一直失效)。

v0.1.5 修的是"**明明没费用,还去拖一张出不起的牌,被游戏拒绝**":

  - 病因不是判据写错,是**发布包里少了一个数据文件**:读费用数字要用的
    10 个数字模板,原来放在 `shots/kredits/samples_r1/` 下,而 `shots/` 是排查用的
    临时目录、**不进发布包**。于是每一个发布包都载入 **0 个模板** ->
    费用**一次都没真读到过**(日志里全是"上一回合 +1"推算)->
    攻击和前进花的钱没人记 -> 账本比真实费用高 -> 拖出去被拒绝。
  - 离线判据:60 张实机存帧喂给读数器,修之前 **0/60 读出来**,
    修之后 **48/60**(剩下 12 张根本不是对局画面,画面上没有数字可读)。
    拿眼睛核对过:徽章上是 `2`,读出来就是 `2`。
  - 修法:模板搬到 **`config/kredits_digits/`**(`config/` 随包发,
    而且总部血量的数字模板 `config/hq_hp_digits/` 早就是这个约定);
    引擎**开跑第一行**会报"费用数字模板:10/10 个数字"或"一个都没载入";
    发布脚本的自检也加上了这个文件。**不用重打 exe**(改的是引擎,不是面板)。

v0.1.4 只加了一件事:**面板一开起来,后台自己先查一次**。
查到新版本就把右上角那个按钮直接改成「有新版本 vX」,点一下就开下载页;
没查到就**什么都不说**(所以"没提示"只意味着"没有新版本"——
真的查不到时,手动点一下按钮,它会老老实实告诉你为什么查不到)。
每次查完都会往 `logs\update_check.log` 追加一行,包括开机那一次 ——
这样"没有新版本"和"那个后台任务根本没跑"能分得开。

v0.1.3 把"检测更新"真的做出来了(以前点了只会告诉你"更新源还没配置"):

  - 读 GitHub 的发布信息,和本地版本号比。版本号按**数字**比,所以
    "0.1.10 比 0.1.9 新"这种判断是对的(按字符串比会得出相反结论);
  - 有新版本就说清楚版本号、包多大,并把按钮变成「打开发布页」;
  - **不自动下载、不自动替换**:包里是 130 MB 的便携目录,替换运行中的自己
    在 Windows 上换不干净,换一半就是个坏包,用户看到的现象是"双击没反应";
  - **查不到就说查不到**:没网 / 超时 / GitHub 限流 / 代理拦截页 / 仓库没发过
    Release —— 每种都有各自的话,**绝不会**把它说成"已是最新";
  - 未登录的 GitHub 接口每小时只有 60 次调用(按 IP 算),所以 API 被限流时
    会自动退到**另一个不限流的地址**(releases.atom),照样能告诉你有没有新版
    —— 代价是那条路上拿不到"包多大"。

v0.1.2 修的是"**手里有能出的牌,它却整回合不出**"这一族毛病 —— 实机跑了几局,
拿日志和截图逐帧对出来的,一共四处:

  - **发布包里漏了卡库**(card_db_test\kards_data.json)。这个文件不在包里时引擎
    **不报错**,只是"卡名 -> 费用"整条路悄悄失效,费用只剩一条不稳的兜底路,
    于是好几个回合一张牌都出不去。现在文件随包发,**引擎开局第一行也会报**
    "卡库:1558 张卡名"还是"卡库没载入",以后这种毛病一眼就能看见;
  - **卡名匹配的"精确"那一级一直没生效**:库里有 659 张卡名带空格(比如"第 5 步兵旅"),
    而程序拿"去掉空格的读法"去比"带空格的原名",永远不相等 -> 掉进模糊匹配 ->
    被一张更长的、恰好包含它的卡名抢走(实测"第 5 步兵旅"被认成"维尔纽斯第 5 步兵旅",
    2 费认成 6 费 -> 判"出不起" -> 那张牌整局都不出)。现在库里 1558 张名字都能认出自己;
  - **卡名只差一个字就整张认不出**:OCR 常把"喷火 Mk Ia"读成"喷火 Mkla"(字母 I 读成 l)、
    把"燧"读成"燃"。现在加了"近似命中"这一级,**但要求明显优于第二名,分不清就宁可不认**;
  - **手牌记忆把"是单位、但费用没读出来"当成"出不起",以后每回合都不再看它一眼**
    —— 一张牌只要有一次没读准,就**整局再也出不去**。现在这类牌每回合都会重新看一眼。
  - 顺带:手牌扇形的左右边缘检测换成"锚点 + 向外延伸",最外那张牌只露出一条窄缝时
    也能量准(以前会把 7 张手牌量成 4 张,那一回合白扫)。

  已知还没解决:手牌 **8 张和 9 张**靠外边缘分不开(两者几乎重合),偶尔会少数一张,
  那一回合可能少出一次牌。这一条还在查(要改成"直接数牌",不再量边缘)。

v0.1.1 修的是 v0.1.0 一个很要命的毛病:那个包把开发机上的 .venv 一起打了进去,
而 Python 的虚拟环境**换台机器就不能用**,所以下载的人点"开始"会立刻停,
只显示"退出码 103"。现在换成了随包携带的便携 Python,并且:

  - 面板启动引擎前会真的试跑一次解释器,不对就直接说清哪儿不对、该怎么办;
  - 解释器坏掉时不再是干等一个裸退出码,会当场把日志尾巴一并显示出来;
  - 解压到**带中文的目录**也能跑了(v0.1.0 在中文路径下读不出任何模板图,
    引擎会安静地什么都认不出来);
  - install.cmd 遇到坏的 .venv 会自己删掉重建,不再"已经有一个了,直接用"。
