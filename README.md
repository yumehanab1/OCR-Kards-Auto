# KARDS AUTO

[![Release](https://img.shields.io/github/v/release/yumehanab1/OCR-Kards-Auto?label=release)](https://github.com/yumehanab1/OCR-Kards-Auto/releases)
[![License](https://img.shields.io/github/license/yumehanab1/OCR-Kards-Auto)](LICENSE)

KARDS（PC 版，Windows 64 位）的离线自动打牌工具。程序截取游戏画面，识别当前界面和场上局面，
再用模拟鼠标完成出牌、上前线、攻击、结束回合。

- **不读游戏内存**，不修改游戏文件，不向游戏进程注入任何东西 —— 所有判据都来自屏幕画面。
- **全程离线**。唯一的联网行为是面板上的「检测更新」，不用它就不联网。
- **每一步都写日志**（`logs\main_loop.log`），出问题可以逐行对照。

> 本仓库是**源码仓库**：不含便携 Python（约 300 MB），也不跟踪面板 exe。
> 想直接跑，请下载 [Releases](https://github.com/yumehanab1/OCR-Kards-Auto/releases) 里的
> `kards-auto_vX.Y.Z_x86_64.zip`（约 130 MB，含便携 Python 和 exe，解压即用）。
> 想改代码，看下面的[从源码跑](#从源码跑)和 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 快速开始

### 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11，64 位（只在这个组合上实测过） |
| 游戏 | KARDS 电脑版；游戏内分辨率调成 **1280x720**，显示模式选窗口 |
| 显示 | 窗口化、无边框、全屏都可以；游戏内 UI 缩放保持默认 |
| 语言 | 简体中文界面 |
| Python | 不需要，发布包自带便携 Python |
| 管理员权限 | 通常不需要。**例外**：如果游戏或 Steam 以管理员身份运行，面板也必须以管理员身份运行，否则 Windows 会拦截对游戏窗口的点击与尺寸调整 |

### 三步开始

1. 打开 KARDS，停在主界面就行；设置里分辨率调到 1280x720，显示模式选窗口。
2. 双击 `KARDS AUTO.exe`，弹出面板窗口。
3. 在面板上把「跑几局」填好，点**开始**。

之后选牌组、排队、换牌、打完整局、结算、再开一局都由程序自己完成。

### 面板说明

右上角三个按钮：

| 按钮 | 作用 |
|---|---|
| 检测更新 | 读 GitHub 发布页，与本机版本号按**数字**比较（所以 `0.1.10` 比 `0.1.9` 新）。有新版本会显示版本号和包大小，按钮变成「打开发布页」。**不会自动下载，也不会自动替换正在运行的自己**。查不到（无网络 / 超时 / GitHub 限流 / 代理拦截）时会说明具体原因，不会谎称「已是最新」 |
| 开始 | 启动引擎进程 |
| 停止 | 结束引擎进程。当前那一下鼠标动作可能停在半路（比如牌拖到一半），重开一局即可 |

左栏「功能选择」对应的就是引擎的命令行参数：

| 开关 | 参数 | 默认 | 说明 |
|---|---|---|---|
| 自动打完一局 | `--play` | 开 | 部署 + 出牌 + 结束回合；不勾只观察、不动作 |
| 攻击 | `--attack` | 开 | 按规则表挑攻击者和目标，含守护 / 拦截判据 |
| 惰性扫描 | `--fast-scan` | 开 | 找到第一张出得起的牌就停手；关掉则每回合读完整手牌（慢，但信息全，排查时有用） |
| 结束回合 | `--end-turn` | 关 | 出完牌主动点「结束回合」；不点就等游戏自己的回合计时 |
| 只看不动(**调试用**) | `--dry-run` | 关 | **调试用**：只记决策，绝不动鼠标。平时不需要开 —— 要真打就得关掉它 |
| 跑几局 | `--max-rounds` | 3 | 填 0 表示一直跑下去。**按「整局」算**：出现胜 / 负结算才 +1，**不是回合数**（一局没结算完就永远不会停） |

一个开关都不勾就点开始，会被拒绝并提示「至少勾一个再开始」。

中间「实时状态」显示：识别到的界面、费用读数、我方支援线张数、最近一个动作、本段跑了几局、
本次启动的完整参数。底部标签「本段干净」表示没有异常行；显示「值得看一眼 N」表示日志里出现了
异常，建议自己翻一眼。

右边「日志」是 `logs\main_loop.log` 的实时尾巴，上面两个小按钮分别是「只看关键行」和「到底部」。

### 术语

文档和日志里会反复出现这几个词：

| 词 | 含义 |
|---|---|
| 前线 | 画面上三条卡行里的中间那一行，双方争夺，同一时刻只有一方占。**被敌方占着时，我方单位上不去** |
| tick | 主循环的一轮：抓帧 → 识别界面 → 执行一个动作 → 短暂休眠。一个阶段通常占一个 tick |
| 惰性扫描 | 从左到右悬停手牌，找到第一张「出得起且可部署」的牌就停手（`--fast-scan`）。关掉即「全量扫描」 |
| 费用徽章 | 单位卡左上角深色小方块里的数字。**橙色** = 本回合未行动且付得起行动费；**灰色** = 已行动 / 刚部署（无闪击）/ 费用已归零 |
| 单实例锁 | 引擎启动时申请的命名互斥体，保证同一时刻只有一个引擎在驱动这台机器的鼠标 |
| `state -> None` | 当前画面认不出来。此时引擎什么都不做（fail-closed），不会照假画面乱点 |
| `blank frame` | 抓到的画面是空的 —— 游戏窗口被最小化或被完全遮挡 |
| 存帧 / `shots\` | 排查用的截图目录。不进仓库，也不进发布包 |

## 使用约束

这一节都是实测踩出来的，每条都会直接影响能不能跑。

**1. 别让别的窗口盖住游戏。** 抓屏是直接抓屏幕的，窗口被完全挡住时会抓到别人的画面，
于是引擎按设计什么都不做，日志写：

```
⚠️ KARDS 窗口不可见/被遮挡 -> 本 tick 不动作。…… 请把 KARDS 置于最前,别让别的窗口盖住它。
```

面板、资源管理器、浏览器、模拟器窗口都会挡住它。把面板拖到旁边，或者点完「开始」就把游戏切到前台；
重新看得见后，引擎会自己接着跑并写一行「✅ KARDS 窗口恢复可见」。**游戏窗口也别最小化**，
最小化时日志会写 `blank frame`。

**2. 同一时刻只能跑一个引擎。** 两个引擎会抢同一个鼠标，扫描会被自己人打断。引擎启动时会申请
单实例锁，第二个实例会被拒绝启动。如果日志里出现「已经有一个 main_loop 在跑了」，它会直接写出
占用者 PID 和一条可以照抄的命令（`taskkill /PID 1234 /F`），不需要去任务管理器翻进程。

**3. 跑的时候别动鼠标。** 扫描的每一步都会检查用户是否在操作鼠标，一旦发现就立刻中止让路
（日志写「用户在操作鼠标 -> 中止让路」），那一回合的扫描作废。

**4. 游戏要在前台。** 不在前台时，点下去会落到别的窗口上 —— 表现是「鼠标在动，游戏却没反应」。

**5. 风险。** 这是自动化操作。虽然只是模拟鼠标，理论上仍存在被官方判定为第三方工具的风险。
请用小号、控制单次时长、别无人值守跑一整夜。详见 [NOTICE.md](NOTICE.md)。

## 会做什么，不会做什么

**会：**

- 认出主界面、选牌组、排队、换牌、对局中、结算（胜/负）这几种画面，自己一路点进去；
- 排队超过 12 分钟自动点取消，重新走一遍流程；
- 对局里读费用、扫手牌，把出得起的单位拖到场上；
- 让场上的单位上前线、攻击敌方单位和总部；
- 打不动了就结束回合；一局结束自己开下一局；
- 顺手把升级、任务完成那类弹出的尾巴页点掉。

**不会：**

- 不会读对手的牌，也不做任何战术推演。策略很朴素：能出的出、能打的打、打不动就过；
- 不会用需要手动选目标的指令卡；
- 不会自动登录、不会自动更新、不改你的游戏设置；
- 不认识中文以外的游戏语言，也不认识改过 UI 缩放比例的界面；
- 不会自动下载或安装新版本（检测到新版本只给下载页地址）。

## 排障

面板右边就是日志。要看全文就打开 `logs\main_loop.log`（引擎写的）或 `logs\gui_run.log`
（面板把引擎输出原样抄的一份）。

| 日志里看到 | 意思 | 怎么办 |
|---|---|---|
| `state -> None` 一直重复 | 认不出当前画面，多半是游戏弹了公告 / 活动 / 升级窗口挡在前面 | 关掉那个窗口 |
| `blank frame - window minimized/occluded?` | 抓到的画面是空的 | 让游戏窗口可见（别最小化、别被遮挡） |
| `⚠️ 没找到 kards 窗口` | 游戏没开 | 打开游戏 |
| `⚠️ KARDS 窗口不可见/被遮挡 -> 本 tick 不动作` | 见上面的使用约束第 1 条 | 把游戏置于最前 |
| `[attack] 没找到橙色费用徽章 -> 不攻击` | 不是你的回合，或者画面还停在动画上 | 不用管，它自己会重试 |
| 鼠标在动，游戏却没反应 | 游戏不在前台 | 点一下游戏窗口，回面板点「停止」再「开始」 |
| `❌ 已经有一个 main_loop 在跑了` | 上一次的引擎进程还活着 | 照抄日志里给出的 `taskkill /PID <pid> /F` |
| `⚠️ …… 这一下没点成` | 系统拒绝了鼠标动作（`SetCursorPos` / `SetWindowPos` 被拒） | 用**管理员身份**运行面板，或者让 Steam / 游戏用普通权限运行 |
| `卡库没载入` / `费用数字模板:0/10` | 发布包缺文件（历史上发生过两次） | 重新下载完整发布包；顺手把日志发给作者 |
| traceback / `[in_game] turn engine error` | 引擎内部错误，一般不影响整局继续跑 | 把日志整份发给作者 |

**最有用的一招**：把 `logs\` 里最新的日志整份发给作者，基本上一眼就能看出卡在哪。
提 issue 请用 [bug 报告模板](https://github.com/yumehanab1/OCR-Kards-Auto/issues/new/choose)。

## 目录结构

发布包解压之后是这个样子：

| 路径 | 是什么 | 能不能删 |
|---|---|---|
| `KARDS AUTO.exe` | 面板。**只是个面板**，真正干活的是它去调 Python 跑 `src\main_loop.py` | 不能 |
| `src\` | 引擎代码，运行时真的会读它 | 不能 |
| `config\` | 界面模板、识别参数、版本号、数字模板 | 不能（删了要重新录） |
| `ui_templates\` | 按钮和图标的小图 | 不能 |
| `card_db\` | 卡库 `kards_data.json`（卡名 → 费用） | 不能。2026-09 从 `card_db_test\` 改名而来 —— 它是**运行时必需**的文件，不是测试夹具 |
| `python\` | 便携 Python + 全部依赖，约 300 MB（只在发布包里，仓库里没有） | 不能 |
| `assets\` | 图标 | —— |
| `logs\` | 运行日志 | 可以删，程序会重建 |
| `docs\` | 设计文档与历史记录，改代码的人会看 | —— |
| `dev\` | 开发与排查脚本，跑游戏用不到 | 可以删 |
| `install.cmd` | 一键装依赖。从源码跑才需要 | —— |
| `build_gui.bat` | 重新打包 exe，只有改了 `src\gui.py` 才需要 | —— |
| `calibrate.cmd` / `snap-kards.cmd` | 重新标定识别区域，平时用不到 | —— |
| `requirements.txt` | 依赖清单（装依赖交给 `install.cmd`） | —— |

**要紧的一句**：`python\`、`src\`、`config\`、`ui_templates\`、`card_db\` 一个都不能少。
整个文件夹一起挪、一起拷都没问题（便携 Python 的路径全跟着自己的位置走），但**别只把 exe 拎出去**。

## 从源码跑

仓库里没有 `python\`（git 不放几百 MB 的二进制），所以 clone 之后要先装依赖：

```cmd
install.cmd
```

它会自己找 Python、建一个 `.venv`、装包，最后 import 一遍确认没坏。两个可选参数：

```cmd
install.cmd minimal    :: 只装跑引擎必需的那四个包，最快
install.cmd mirror     :: 走清华镜像，国内网络快很多
```

要求 **Python 3.10 以上**。没装的话脚本会告诉你去哪下载，装的时候记得勾上
「Add python.exe to PATH」。

装完之后面板会按 **便携 Python → `.venv` → PATH 里的 Python** 这个顺序找解释器，而且每一档
都真的试跑一次，坏的会跳过 —— 所以「某个环境是坏的」不会让整个面板用不了。

> **关于 OCR 依赖**：`rapidocr_onnxruntime` 在 PyPI 上声明的 Python 支持上限是 3.12，
> 在更新的版本上 pip 有时会说「找不到可用版本」。这不绝对 —— 发布包自带的 Python 3.14 上
> 就装上了。真装不上也不影响跑，只是少一个读卡牌文字的功能，`install.cmd` 会跳过它继续。

### 改代码之后

| 改了什么 | 要不要重打 exe |
|---|---|
| `src\gui.py`（面板：界面和逻辑都在里面） | **要**，双击 `build_gui.bat`。面板是编进 exe 的，不重打用户看到的还是旧面板 |
| 其它 `src\*.py`（引擎） | 不用。面板每次「开始」都是去跑项目里的 `src\main_loop.py` |

## 版本与更新

当前版本号写在 `config\app_version.json`，**以那个文件为准**；每个版本的变更记录见
[CHANGELOG.md](CHANGELOG.md)。

「检测更新」会去 GitHub 读本项目的发布页并与本机版本号比较。想让别处也能查，把
`app_version.json` 里的 `update_url` 填成你自己的地址即可（留空 = 用 GitHub）。
面板启动后会在后台自动查一次，查完往 `logs\update_check.log` 追加一行 —— 这样「没有新版本」
和「那个后台任务根本没跑」能分得开。
